# 처음 사용하기

첫 목표는 기본 예제로 파일 세 개를 만들어 확인하는 것입니다. 플러그인을 지원하는 Codex와 Node.js 20 이상·npm을 준비하세요.

## 1. 설치

터미널에서 실행합니다.

```sh
codex plugin marketplace add https://github.com/jkwon-startup/office-maker --ref v0.1.1
codex plugin add office-maker@office-maker-local
```

새 대화의 스킬 선택 목록에서 **한 번에 만들기**를 선택합니다. 목록이 갱신되지 않으면 Codex를 다시 실행하세요. 호스트에서 이름 공간을 붙여 보여 주면 목록의 실제 이름을 사용합니다.

## 2. 예제 요청

스킬을 선택한 대화에 복사하세요.

```text
$osmu-maker
함께 제공하는 가상 업무 개선 워크숍 예제로 PPT·엑셀·워드를 만들어줘.
examples/synthetic/input.json의 제작안과 템플릿을 그대로 사용해줘.
추가 웹 조사는 하지 마.
결과는 현재 작업 프로젝트의 outputs/office-demo에,
체크포인트는 work/office-demo에 저장해줘. 필요한 실행 환경도 준비해줘.
```

스킬이 설치된 본체 위치를 찾고 의존성을 확인합니다. 처음에는 허용된 위치에 의존성을 설치합니다. 설치 위치가 읽기 전용이면 선택한 작업 공간의 비공개 폴더에 실행 복사본을 준비합니다. 사용자에게 캐시 폴더를 직접 찾아달라고 요구하지 않습니다. 호스트에서 권한 승인이 필요하면 화면의 안내를 따르세요.

## 3. 결과 확인

대화의 파일 링크를 열거나 지정한 `outputs/office-demo` 폴더를 확인하세요.

| 파일 | 예제 내용 |
| --- | --- |
| `ppt.pptx` | 비교·로드맵·가상 지표를 포함한 5장, 발표자 노트 5개 |
| `excel.xlsx` | 실행 계획과 가상 계산의 2시트, 절감 시간·절감률 수식 |
| `word.docx` | 기본 보고서 양식의 5절, 실행 계획표 |

수치는 계산 연습용 가정이며 실제 성과가 아닙니다. [미리보기와 검토 범위](../examples/synthetic/expected-results.md)를 참고하세요. 세 파일 생성 완료와 실제 앱의 화면 검토 완료는 구별됩니다.

반복 실행은 같은 입력·결과 폴더·체크포인트를 사용하면 기존 성공 파일을 재사용합니다. 입력을 바꾸면 새 결과 폴더와 체크포인트를 선택하세요. 기존 파일은 덮어쓰지 않습니다.

## 다음에 해볼 것

### 내 자료로 하나만 만들기

원하는 스킬을 선택하고 자료를 첨부하세요. 예를 들어 다음과 같이 요청할 수 있습니다.

```text
$word-maker
첨부 자료로 의사결정용 보고서를 만들어줘.
먼저 필요한 입력과 사용할 보고서 양식을 물어봐줘.
```

목적·독자·범위·필수 내용·템플릿·저장 위치 중 빠진 중요한 항목만 묻습니다. 답변 후 제작하며 선택 항목은 “추천값으로 진행”이라고 할 수 있습니다.

### 템플릿 선택·등록

| 형식 | 이름 | 고정 ID | 선택 번호 |
| --- | --- | --- | --- |
| PPT | 기본 발표 | T001 | 1 |
| 엑셀 | 기본 실행표 | E001 | 1 |
| 워드 | 기본 보고서 | W001 | 1 |

번호는 목록 순번이 아니라 ID의 숫자 부분입니다. “추천”은 목적에 맞는 구성과 기본 중립 디자인을 뜻하며 반드시 기본 보고서의 목차를 강제하지 않습니다.

자신의 양식 파일을 여러 개 주고 “개인 템플릿으로 등록해줘”라고 요청할 수 있습니다. 스킬이 실제 파일을 분석하고 지원되는 디자인·구성을 프로필로 정리합니다. [PPT 규칙](../skills/ppt-maker/references/template-library.md), [엑셀 규칙](../skills/excel-maker/references/workbook-rules.md), [워드 규칙](../skills/word-maker/references/document-rules.md)을 따릅니다. 자동 추출·등록 전용 CLI는 현재 없습니다.

개인 원본·목록의 저장 위치를 지정하세요. 실제 검토를 마친 버전만 ready로 사용하며 공개 소스에 고객 파일을 넣지 않습니다. 프로필 방식은 원본 Office 파일을 그대로 복제하는 기능과 다릅니다.

### 나만의 호출 이름

예를 들어 “PPT 스킬의 호출 이름을 my-ppt로 만들고 싶어”라고 요청하세요. 개인 스킬 폴더를 지정하면 스킬이 생성 예정 파일을 먼저 보여 주고 해당 호스트의 권한 규칙에 따라 별칭을 만듭니다. 호스트가 새 별칭을 발견한 후 `$my-ppt`로 호출합니다. 기존 본체 위치가 바뀌면 별칭을 다시 만드세요. 이 기능이 ChatGPT 설치를 자동화하지는 않습니다.

## 문제가 생기면

- `plugin` 명령이 없음: 해당 Codex 버전의 플러그인 지원과 공식 안내를 확인하세요. [개발자 안내](development.md)에 소스 실행 경로도 있습니다.
- 스킬이 안 보임: 설치 결과와 새 대화의 선택 목록을 확인하세요. 대화에 이름을 적는 것만으로 설치되지는 않습니다.
- 의존성 준비 실패: Node.js 20 이상·npm, 네트워크 접근, 실행 폴더의 쓰기 권한을 확인하세요. 설치 실패 상태에서 파일 생성 성공으로 표시하지 않습니다.
- 저장 충돌: 새 폴더를 지정하거나 동일 입력의 기존 체크포인트로 재개하세요.
- 글꼴·줄바꿈 차이: 사용 중인 Office 앱과 글꼴을 확인하세요. 기본 폰트 파일을 패키지에 포함하지 않습니다.

[GitHub Issues](https://github.com/jkwon-startup/office-maker/issues)에 버전·환경·재현용 가상 입력과 오류 메시지를 남길 수 있습니다. 실제 고객 자료·개인 경로·비밀키는 제외하세요.

ChatGPT에서는 스킬 선택과 파일 실행 도구를 지원하는 환경이 필요합니다. 실행 도구가 없는 대화에서는 제작안을 받을 수 있으나 실제 파일 생성은 수행되지 않습니다. 지원하는 ChatGPT 환경의 대화형 동작은 별도 검증 대상입니다.
