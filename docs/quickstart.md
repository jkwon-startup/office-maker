# 처음 사용하는 고객을 위한 안내

Office Maker 0.1.0은 Codex의 파일 실행 환경을 중심으로 한 초기 공개 버전입니다. Node.js 20 이상과 npm, 스킬을 실행할 수 있는 Codex가 필요합니다. Microsoft Office는 생성에 필수인 의존성이 아니지만 결과의 앱 호환성을 확인할 때 사용합니다.

## 1. 전체 묶음을 준비한다

[GitHub 저장소](https://github.com/jkwon-startup/office-maker)의 전체 묶음을 내려받습니다. 버전을 고정하려면 릴리스 v0.1.0을 사용합니다. `skills/`의 한 폴더만 복사하지 않습니다. `common/`, `pipelines/`, `tools/`, `package.json`, `package-lock.json`과 `plugin.json`이 필요합니다. 실제 고객 자료를 넣지 않은 깨끗한 배포본에서 설치합니다.

패키지 루트의 터미널에서 실행합니다. Windows에서도 Node와 npm 설치 후 같은 명령을 사용할 수 있습니다.

```sh
npm ci --ignore-scripts
npm run doctor
npm test
npm run release:check
```

`doctor`는 Node와 라이브러리의 사용 가능 여부를 검사합니다. 글꼴 설치, 문서 화면, 스킬이 호스트에 나타나는지까지 검사하지는 않습니다.

## 2. Codex에서 스킬을 발견하게 한다

플러그인 기능이 있는 Codex CLI에서는 패키지 루트에서 다음 명령으로 마켓플레이스를 추가하고 설치합니다. 이 단계는 **사용자의 로컬 Codex 설치와 설정**을 변경합니다.

```sh
codex plugin marketplace add .
codex plugin add office-maker@office-maker-local
codex plugin list --json
```

GitHub에서 마켓플레이스를 직접 가져오려면 첫 번째 명령을 다음으로 바꿉니다.

```sh
codex plugin marketplace add https://github.com/jkwon-startup/office-maker --ref v0.1.0
```

CLI에서 `plugin` 명령을 지원하지 않으면 해당 호스트의 공식 플러그인 안내를 따릅니다. 데스크톱에서는 이 프로젝트를 열고 Plugins 화면에서 `Office Maker` 소스를 확인합니다. 목록 변경 후 새 대화 또는 앱 재시작이 필요할 수 있습니다. 실제 플러그인 설치는 원본과 별도의 캐시 복사본을 사용할 수 있습니다. 실행자가 **발견된 SKILL.md의 위치를 기준으로 패키지 루트**를 찾고 그 위치에서 `npm ci --ignore-scripts`와 `npm run doctor`를 실행하도록 합니다. 원본 저장소에서의 설치 검사는 캐시 복사본의 의존성 설치를 대신하지 않습니다.

호스트가 표시하는 스킬 선택 목록에서 `PPT 만들기`, `엑셀 만들기`, `보고서 만들기`, `한 번에 만들기`를 선택합니다. Codex의 기본 호출 이름은 `$ppt-maker`, `$excel-maker`, `$word-maker`, `$osmu-maker`이며 플러그인 설치 시 호스트가 이름 공간을 표시하면 그 이름을 선택합니다. 스킬 이름을 대화에 적는 것만으로 설치가 이루어지지는 않습니다.

공식 안내: [스킬 발견과 배포](https://learn.chatgpt.com/docs/build-skills), [패키지와 마켓플레이스](https://developers.openai.com/plugins/build/plugins).

## 3. 스킬의 질문에 답한다

가상 예제로 시작하려면 스킬을 선택한 뒤 다음과 같이 요청합니다.

```text
가상의 업무 개선 워크숍 자료를 PPT·엑셀·워드로 만들어 주세요.
목적: 참가자가 작은 업무 개선 하나를 실행하도록 돕기
독자: 일반 실무자
자료: examples/synthetic/input.json, 추가 웹 조사 없이 사용
PPT 역할: 발표용 5장, 발표자 노트 포함
엑셀 역할: 실행 과제 추적표, 임의 담당자나 수치 생성 금지
워드 역할: 목적·핵심 내용·다음 행동을 설명하는 보고서
템플릿: 세 형식 모두 기본 중립 디자인 추천
언어: 한국어
선택 항목은 추천값으로 진행하고, 필수 정보가 빠졌으면 먼저 질문해 주세요.
저장 위치는 제가 지정한 개인 작업 폴더를 사용하고 제작 전에 전체 경로를 알려 주세요.
```

자료·목적·독자·템플릿·저장 위치 중 중요한 정보가 빠지면 AI가 질문하고 답을 기다립니다. 세 형식의 질문을 반복하지 않고 공통 입력을 공유합니다. 제작 스크립트는 완성된 JSON 계획을 파일로 변환하며 자체적으로 AI를 호출하거나 원문에서 자동으로 보고서를 쓰지는 않습니다.

## 4. 템플릿을 여러 개 등록한다

실제 템플릿 파일과 분석 결과는 사용자가 지정한 **개인 라이브러리**에 둡니다. 공개 템플릿 목록은 처음에는 비어 있습니다. 사용자가 파일을 주면 AI는 실제 항목·디자인을 분석하고 각 형식의 `schemas/template.schema.json`에 맞춰 프로필을 작성합니다. 자동 원본 추출·등록 CLI는 현재 포함되지 않습니다.

PPT는 `T001`, 엑셀은 `E001`, 워드는 `W001`처럼 고정 ID를 사용합니다. 사용자는 등록된 이름 또는 번호로 선택할 수 있습니다. 번호 2는 각각 T002/E002/W002를 뜻하며 목록의 둘째 줄을 뜻하지 않습니다. 중복 이름은 ID로 다시 확인합니다. 검토하지 않은 버전은 `draft`이고, 개인정보·화면·앱 검토 근거가 있는 버전만 `ready`입니다. 테스트 코드의 가상 `passed` 값은 실제 템플릿의 검토 근거가 아닙니다.

워드는 `report.sections`에 필수 절·제목·순서·표 머리글을 보존합니다. 지원하는 방식은 디자인 프로필을 적용한 **새 문서 생성**입니다. 원본 문서의 마스터·로고·머리말·복잡한 배치를 그대로 재사용하는 기능은 없습니다.

## 5. 나만의 호출 이름을 정한다

예를 들어 `my-report`라는 별칭을 사용하려면 본체 패키지 루트에서 실행합니다. 아래 자리표시자를 사용자가 선택한 **절대 경로**로 바꾸고 공백이 있으면 따옴표로 감쌉니다. 본체 묶음 밖이며 호스트가 발견하는 개인 스킬 상위 폴더를 사용합니다.

```sh
node tools/create-alias.mjs --name my-report --input word-maker --dest "<개인 스킬 상위 폴더의 절대 경로>" --dry-run
node tools/create-alias.mjs --name my-report --input word-maker --dest "<개인 스킬 상위 폴더의 절대 경로>"
```

생성 경로를 먼저 확인한 뒤 실행합니다. 별칭은 호스트가 발견한 후 `$my-report`로 호출하며 본체의 설치 위치를 참조합니다. 패키지를 이동하거나 업데이트 경로가 바뀌면 다시 생성합니다. ChatGPT 설치를 자동화하거나 임의의 `/명령`을 등록하는 도구는 아닙니다.

## 6. 결과를 확인한다

CLI만 확인할 때는 다음 가상 예제를 사용할 수 있습니다. `outputs/demo`와 `work/demo`는 공개 Git에서 제외됩니다. 실제 업무에서는 공개 패키지 밖의 개인 경로를 권장합니다.

```sh
npm run osmu -- --input examples/synthetic/input.json --output outputs/demo --run-dir work/demo
```

같은 명령을 다시 실행하면 체크포인트와 결과 해시가 일치하는 성공 파일은 재생성하지 않습니다. 입력을 변경했다면 새 결과·작업 폴더를 지정합니다. 기존 파일을 자동으로 덮어쓰지 않습니다. 실패한 형식이 있으면 종료 코드 1과 해당 상태를 확인합니다.

PPT는 내용·출처·발표자 노트, 엑셀은 데이터 형식·수식 참조·실제 재계산 값, 워드는 필수 항목·순서·표를 확인합니다. 세 파일 모두 사용할 앱에서 한글·줄바꿈·표·페이지를 확인합니다. ExcelJS는 수식을 계산하지 않습니다. 계산 캐시가 없는 수식은 Excel 또는 호환 앱에서 재계산해야 합니다. LibreOffice 검사는 Microsoft Office 검사를 대신하지 않습니다. Linux/헤드리스 환경의 한글 표시 문제는 렌더러가 실제 시스템 한글 글꼴에 접근할 수 있는지도 확인합니다. 폰트를 패키지에 무단 포함하지 않습니다.

## ChatGPT와 문제 해결

스킬 지원 ChatGPT에서는 스킬 선택 UI 또는 `@` 선택을 사용합니다. 일반 ChatGPT 대화에 로컬 스킬 폴더를 올리는 것만으로 Node가 실행되지는 않습니다. 해당 세션의 파일 실행 환경과 설치 정책을 먼저 확인합니다. 실행할 수 없다면 요구사항과 JSON 제작안까지만 제공하고 파일 생성 성공으로 표시하지 않습니다. ChatGPT에서의 전체 실행은 별도 호스트 검증 항목입니다.

`Missing dependency`는 실제 실행 패키지 루트에서 `npm ci --ignore-scripts` 후 `doctor`로 확인합니다. 스킬이 보이지 않으면 마켓플레이스·설치 상태와 새 대화의 선택 목록을 확인합니다. 템플릿 이름이 모호하거나 미검토라면 임의로 기본 디자인으로 바꾸지 않습니다. 문의 시에는 재현용 **가상 입력**, 버전, 오류 코드와 환경을 제공하고 원본 고객 자료·개인 경로·비밀키를 제외합니다.
