# 통합문서 제작·분석 규칙

필요한 절만 읽는다. 데이터 계약은 `../schemas/workbook.schema.json`, 템플릿 계약은 `../schemas/template.schema.json`이다. 이 문서는 실행자가 수행할 검토를 설명하며, 모든 항목이 자동 검사 코드로 구현됐다는 뜻이 아니다.

## 1. 계약과 기본 생성기의 범위

통합문서에는 title과 sheets가 있다. 선택적 template 및 mode를 전달한다. 각 시트에는 name, columns, rows가 필요하며 행은 열 key를 사용하는 객체다. 열에는 key, header, 선택적 width·numberFormat이 있다. 출처와 업무 정책은 이 계약이 허용하는 별도 시트로 표현한다. 출처·개인정보를 임의의 최상위 키로 추가하지 않는다.

시트명은 31자 이하이며 `\ / ? * [ ] :`를 쓰지 않는다. 대소문자만 다른 중복 이름과 중복 열 key를 거부한다. 실제 Excel의 이름·셀 제한과 사용자 대상 앱도 확인한다. 헤더 행을 데이터 rows에 중복 삽입하지 않는다.

셀은 문자열·유한 수·참/거짓·null 또는 `{ "formula": "B2*2", "result": 4 }`다. 수식은 `=` 없이 명시한다. result는 선택 사항이며 검증된 캐시 값일 때만 넣는다. 캐시가 없으면 앱 재계산이 필요함을 표시한다. ExcelJS는 수식을 계산하지 않는다. 함수명·인수 구분은 지원되는 엑셀 수식 문법을 따른다. 외부 참조나 동작을 유발하는 수식은 일반 입력 문자열에서 자동 생성하지 않는다.

기본 엔진은 여러 시트·행·열 폭·숫자 형식·머리글 서식·필터·첫 행 고정·인쇄 방향을 지원한다. 차트·피벗·조건부 서식·병합·원본 구조 재사용은 지원하지 않는다. 날짜 객체는 현재 JSON 셀 계약에 없으므로 ISO 형식 문자열 등 지원되는 표현을 사용한다. 실제 날짜 셀이 필요하면 검증된 도구·계약 확장을 먼저 마련한다.

## 2. 원자료 읽기와 정규화

지원 도구로 실제 파일을 읽어 시트 목록, 자료형, 머리글 위치, 수식과 캐시, 병합·숨김 요소를 확인한다. CSV는 인코딩·구분자·인용부호·날짜·소수점·천 단위 규칙을 확인한다. 샘플만 읽었으면 전체 파일 분석으로 안내하지 않는다. 필요한 데이터가 없는 경우 질문하고 원본에 없는 값을 채우지 않는다.

- ID·사번·품목 코드는 문자열로 보존해 선행 0과 긴 식별자가 변하지 않게 한다.
- 0, 빈 셀, 빈 문자열, 누락, 해당 없음, 오류를 구별한다.
- 원본값과 정규화값을 구분하고 파일·시트·행·셀로 연결한다. 개인정보가 있는 출처는 비공개 작업 자료에만 둔다.
- 이름만으로 사람을 합치지 않는다. 명시적 고유키가 없으면 매칭 불확실성을 표시한다.
- 중복은 키·기간·업무 기준으로 판정한다. 반복 거래·분할 기록을 중복으로 단정하지 않는다.
- 날짜·시간·시간대·단위·통화 해석을 기록한다. 숫자 서식이 같아도 단위가 다르면 합산하지 않는다.

새 분석 코드는 가상 최소 표본에서 실제 읽기, 반환 형식, 핵심 계산을 먼저 검증한다. 원자료의 행 순서나 셀값이 바뀌어도 근거 위치를 잃지 않게 한다.

## 3. 정제·제외·보류와 집계

각 분석 범위의 원본 데이터 행을 반영·제외·보류 중 하나로 분류한다. 빈 행·헤더·집계 행의 포함 여부를 먼저 정의한다. 원본 행 수 = 반영 + 제외 + 보류로 대조하며, 제외나 보류를 두 번 세지 않는다. 중복·보류가 겹치는 경우 우선순위를 설명한다.

변경 로그는 원본 위치·항목·변경 전후·이유·적용 기준·확정 상태를 가진다. 확인 필요 목록은 대상 역할, 질문, 근거 위치, 결과 영향, 확인 상태를 가진다. 사람 이름이나 담당 역할은 원자료·사용자 지시에 근거하며 추정하지 않는다.

기간·분모·단위·제외·보류 영향과 반올림 순서를 정한 뒤 코드로 계산한다. 금액 계산은 필요한 정밀도에 맞춰 정수 최소 화폐 단위 또는 검증된 십진 연산을 사용한다. 서로 다른 통화는 명시적 환율·기준일 없이 합산하지 않는다. 상세 합계·분류별 합계·요약 합계를 동일 기준으로 대조하고 차이가 나면 원인을 설명한다.

조건부 보류 값은 0원이나 확정값으로 바꾸지 않는다. 확정 가능한 부분, 가계산 합계, 미확정 영향 범위를 구분한다. 합계가 일치한다는 사실만으로 잘못된 정책·누락된 행·개별 금액 오류가 없다고 결론 내리지 않는다.

## 4. 근태·급여 요청일 때만 적용

이 스킬을 인사 업무에만 제한하지 않는다. 근태·급여 요청이 있을 때 아래 조건을 확인한다.

1. 대상 국가·기간, 적용 규정과 시행일, 회사의 근무제·휴일·휴게·승인·가산·반올림 기준을 확인한다. 법적 판단이 필요하면 해당 기간의 공식 법령·행정자료를 확인한다.
2. 출근·퇴근을 완전한 날짜·시각으로 다룬다. 퇴근 시각이 출근보다 빠르거나 같다고 자동으로 다음 날 근무로 바꾸지 않는다. 교대·야간 근무 근거가 있을 때만 보정하고 기록한다.
3. 출퇴근 누락·휴게 불명·사번 불일치·승인 미확정은 보류한다. 휴가·결근·0시간 근무를 서로 구별한다. 직원정보에 없는 사번을 비슷한 이름으로 강제 연결하지 않는다.
4. 급여 계산용 가중 환산시간과 실제 근로시간을 분리한다. 실제 주 근로시간을 연장·휴일 시간이나 환산시간만으로 대체하지 않는다. 연장·야간·휴일이 겹치는 구간은 중복 산입과 가산 규정을 확인한다.
5. 한 주의 시작 요일과 실제 시작·종료 날짜로 집계한다. 월별 자료의 첫·마지막 주는 전후 월의 필요한 자료까지 확인한다. 일부 기간만 있으면 주 단위 판단 불가 또는 잠정이라고 표시한다.
6. 숫자 기준 초과 후보, 회사 규정 초과, 법적 위반 판단을 구분한다. 적용 근무제나 실제 근로시간이 미확인인데 법 위반으로 확정하지 않는다.
7. 시급·통상임금·가산율·휴게·승인·반올림 등 지급액에 필요한 값이 부족하면 확정 수당이라고 표시하지 않는다. 확보된 값으로 가계산할 경우 조건과 제외 영향을 표시한다.
8. 안내문을 요청받으면 확인된 사실과 확인 요청을 담은 초안으로 만든다. 보상휴가 등 조치는 적용 요건과 회사 제도가 확인되기 전 확정 권고하지 않는다. 자동 메일·메시지 전송은 하지 않는다.

필요한 경우 요약·개인별·분류별·기간별·정제 로그·확인 필요·출처/계산 기준 시트를 제안한다. 모든 업무에 같은 시트 개수를 강제하지 않는다.

## 5. 여러 엑셀 템플릿의 등록

공개 라이브러리는 빈 배열로 시작한다. 개인 원본과 개인 목록은 사용자가 지정한 위치에 보관한다. 공개 목록에 자동 합치지 않는다.

- 각각 분석해 중립적 이름과 E001부터 고정 ID를 부여하고, 삭제한 ID를 재사용하지 않는다.
- 같은 디자인 계보의 수정은 새 semver로 등록한다. 기존 버전을 덮어쓰지 않는다.
- 지원 디자인은 font, bodyPt, headerColor, columnWidth, orientation이다. 원본의 수식·서식·업무 구조를 저장·복제하는 기능으로 안내하지 않는다.
- 실제 수행 전 privacy, visual, compatibility는 pending이고 상태는 draft다. 세 검사를 실제 통과했을 때만 ready로 표시한다. 기본 생성기는 draft를 거부한다.
- 가상 내용으로 예시 파일과 실제 검토 화면을 만들 수 있을 때만 검토 근거를 남긴다. 미리보기 없이 검토했다거나 검토용 도구가 존재한다는 이유로 통과 처리하지 않는다.
- 본문·수식·메모·숨김 시트·이름 정의·문서 속성·연결·링크·차트 내장 데이터·이미지·포함 객체·미리보기의 개인정보와 재배포 권한을 확인한다. 검토하지 못한 원본은 공개 자산에서 제외한다.
- 스키마 검사 외에 ID/version 중복, ID의 숫자 표현 충돌, 이름·별칭의 모호성, 실제 지원 디자인을 확인한다.

기본 엔진은 ready design_system 프로필을 사용한다. 원본 파일 분석·등록은 실행자가 사용 가능한 도구로 수행하며 자동 등록 CLI가 포함된 것은 아니다. 사용자가 원본 구조 유지를 요구하면 지원 여부를 먼저 확인한다.

## 6. 파일 검사와 화면 검토

실제 저장한 XLSX를 다시 읽어 중요 셀의 값·자료형·수식·캐시·숫자 형식을 계획과 대조한다. 단순 파일 존재와 시트 수·이름 일치는 최소 구조 검사다. 가능한 앱에서 재계산해 참조 오류·순환 참조·0 나눗셈 등을 확인한다. 미실행 항목은 검증됨으로 표시하지 않는다.

머리글 중복, 항목 잘림, 열 폭·줄바꿈·필터·고정 행·인쇄 방향을 실제 화면 또는 렌더링으로 확인한다. 화면 검토가 안 되면 데이터·파일 검사와 구별하여 안내한다. XLSX와 설명·추가 보고서가 같은 기준·수치·출처를 쓰는지도 확인한다.

경계 표본은 빈 데이터, 0/누락, 선행 0 식별자, 중복 후보, 숫자 형식 혼합, 월 경계 주, 자정 횡단과 퇴근 누락, 수식 캐시 부재, 미확정 계산 기준을 포함한다. 관련 없는 경계 항목은 해당 업무에 강제하지 않는다.

공식 참고: [ExcelJS](https://github.com/exceljs/exceljs#formula-value), [근로기준법](https://www.law.go.kr/법령/근로기준법). 법 적용은 분석 대상 기간의 시행 버전을 따로 확인한다.
