# 템플릿 라이브러리 운영 규칙

이 문서는 여러 템플릿을 등록하고 이름·고정 번호로 선택하는 절차다. 공개 패키지에는 검토된 디자인 규칙과 배포 가능한 자산만 포함한다. 실제 고객 원본과 개인 설정은 패키지 밖의 사용자가 지정한 위치에 둔다.

## 1. 데이터와 저장 경계

- `assets/templates/index.json`: 배포 가능한 템플릿 목록. 초기값은 빈 배열이다.
- `schemas/template.schema.json`: 목록과 디자인 프로필의 JSON Schema 2020-12 계약.
- 등록 항목은 템플릿마다 ID, 중립적 이름, 버전, 상태, 입력 종류, 화면 비율, 제작 모드, 디자인 토큰, 레이아웃, 검토 상태를 가진다.
- 자산 참조는 스킬 루트 기준 상대 경로다. 경로 형식은 `assets/templates/T001/v1.0.0/template.pptx` 또는 같은 폴더의 `preview.png`처럼 고정한다. 공개 파일 이름에 원본 고객 파일 이름을 사용하지 않는다.
- 실제 업로드의 경로·작성자·고객명·문서 내용·계정·연락처를 등록 항목에 기록하지 않는다.
- 개인 라이브러리는 공개 목록과 별도로 관리한다. 제작안의 template 객체에 id·version·library를 지정하면 사용자가 정한 절대 경로의 목록을 읽는다. 기본 엔진은 자산을 읽지 않고 디자인 규칙을 사용한다. 사용자가 위치를 정하지 않았다면 저장 위치를 먼저 합의한다. 개인 컴퓨터의 경로나 계정 정보를 공개 파일에 하드코딩하지 않는다.
- 새 파일을 만들기 전 해당 세션의 권한과 파일 승인 규칙을 따른다. 기존 폴더·파일은 무단으로 덮어쓰지 않는다.

## 2. 여러 파일 등록

1. 첨부된 파일 종류와 실제 접근 가능 여부를 확인한다. 파일을 읽지 못하면 분석했다고 말하지 않는다.
2. 각 파일을 독립적으로 분석하고 범용적 이름을 제안한다. 고객명·회사명·실명에서 이름을 자동으로 만들지 않는다.
3. 기존 목록과 충돌하지 않는 다음 ID를 발급한다. 이름만 다른 동일 디자인은 무조건 중복 등록하지 않는다.
4. 색상, 글꼴, 글자 크기, 비율, 여백, 도형 스타일, 레이아웃의 영역과 반복 패턴을 추출한다.
5. 등록할 디자인 규칙을 개인정보 없는 내용으로 정리한다. 분석 중 읽은 원문을 프로필에 그대로 붙이지 않는다.
6. 원본 활용 모드를 제공하려면 개인정보를 검토한 별도 PPTX를 만들고 실제 구조 재사용을 시험한다. 원본 업로드를 공개 자산 폴더로 그대로 복사하지 않는다.
7. 중립적인 가상 문장과 숫자로 미리보기 및 시험 슬라이드를 만든다. 실데이터나 원본 화면 캡처를 그대로 공개 미리보기로 쓰지 않는다.
8. 형식 검사, 추가 불변조건, 개인정보 검사, 렌더 검토, 실행 호환성 확인을 수행한다.
9. 실제 수행한 검사만 `passed`로 표시한다. 모두 통과해야 `ready`로 승격한다. 미실행 검사는 `pending`이며 상태는 `draft`다.
10. 등록 결과에 ID·이름·모드·검토 상태·실제 미리보기를 표시한다. 검사되지 않은 상태를 완성으로 안내하지 않는다.

디자인 규칙은 텍스트·여백·구성까지 포함한다. 색상 몇 개만 추출하고 원본 디자인을 완전히 재현한다고 주장하지 않는다. 복잡한 마스터, 도형, 애니메이션, 특수 차트 등 지원되지 않는 부분은 등록 결과에서 밝힌다.

## 3. 공개본의 개인정보 검사

확인할 대상:

- 본문·표·차트·노트의 실명, 연락처, 주소, 계정, 식별 가능한 고객 내용.
- 파일 속성의 작성자·수정자·회사·제목 등 식별 정보.
- 메모·댓글·숨김 슬라이드·마스터·레이아웃·대체 텍스트·하이퍼링크.
- 차트의 내장 통합 문서, 포함 객체, 외부 데이터 연결, 파일 관계와 내부 자산 이름.
- 이미지·미리보기·로고·스크린샷의 얼굴, 명찰, 연락처, QR 코드, 화면상의 고객 자료 및 이미지 메타데이터.
- 로그·오류 메시지·예시의 개인 절대 경로와 원본 파일 이름.

Schema의 허용 필드와 경로 제한만으로 개인정보 제거가 완료되는 것은 아니다. 사람 이름·로고·사진의 식별 가능성은 별도 확인이 필요하다. 검사하지 못한 포함 객체가 있으면 해당 원본을 배포 자산에서 제외하거나 `draft`로 남긴다.

공개용 자산이 필요하면 가상 내용으로 새로 구성하는 방식을 우선한다. 원본에서 메타데이터만 삭제하고 안전한 공개본이라고 판단하지 않는다. 이미지·폰트·기타 자산은 재배포 가능 여부도 확인한다. 고객이 파일을 제공했다는 사실만으로 재배포 권한이 있다고 간주하지 않는다.

## 4. 디자인 프로필

`design`에는 다음을 기록한다.

- `colors`: background, heading, text, accent, muted의 6자리 HEX 값.
- `fonts`: heading, body, fallbacks. 실제 사용 가능한 글꼴과 대체 결과는 제작 시 확인한다.
- `typography`: 제목·본문·캡션의 기본 pt 크기.
- `spacing`: 화면 크기로 정규화한 좌우·상하 여백과 요소 간격.
- `shapeStyle`: square, rounded, minimal.

`layouts`는 개별 변형을 보존한다. 각 레이아웃은 고유 ID, 종류, 영역 배열을 가진다. 영역 좌표는 왼쪽 위 기준 0~1이며 x·w는 화면 너비 비율, y·h는 화면 높이 비율이다.

레이아웃 종류: title, body, image_left, image_right, comparison, table, chart, roadmap, kpi, closing. 원본에 없는 레이아웃을 추출한 것처럼 기록하지 않는다. 없는 유형이 필요하면 등록된 토큰으로 새 변형을 만들고 파생 구성이라고 구분한다.

## 5. 모드와 검토 상태

| 모드 | 사용 조건 | 동작 |
| --- | --- | --- |
| design_system | 추출·검토된 디자인 프로필 | 토큰과 영역을 적용해 편집 가능한 슬라이드 구성 |
| original_template | 검토된 PPTX와 구조 재사용 가능한 엔진 | 기존 슬라이드·레이아웃 구조를 유지하며 내용 교체 |

PDF·이미지 입력은 design_system만 지원한다. 원본 PPTX가 있어도 엔진의 재사용 기능이 확인되지 않으면 original_template을 지원한다고 표시하지 않는다. unsupported 모드에서 이미지를 배경으로 깔아 조용히 대체하지 않는다.

ready는 privacy·visual·compatibility 세 검사 모두 실제 통과한 상태다. 툴이 없어서 검사하지 못한 경우 draft로 남긴다. 요청한 템플릿이 draft라면 미검토 항목을 안내한다. 기본 생성기는 draft를 거부하므로 검토를 마치거나 다른 ready 템플릿·중립 디자인을 선택하게 한다.

## 6. ID·버전·이름 선택

- ID는 T001부터 발급하고 삭제 후 재사용하지 않는다. 이전 ID는 retired 항목으로 남겨 이력을 보존한다.
- 사용자가 “1”, “001”, “T001”로 요청하면 ID의 숫자 부분을 해석한다. 표시 순서로 번호를 다시 매기지 않는다.
- 정렬을 바꿔도 ID는 바꾸지 않는다. ID를 재발급하지 않도록 중간 retired 항목도 유지한다.
- 같은 ID는 디자인 계보를 나타내며 버전은 세 자리 숫자의 의미 있는 버전 체계다.
- 수정은 새 버전으로 등록한다. 기존 버전은 덮어쓰지 않는다.
- 버전 미지정 시 해당 ID의 가장 최신 ready 버전을 선택한다. ready 버전이 없으면 그 사실을 알린다.
- PPT 수정은 해당 PPT가 사용한 ID·버전을 유지한다. 사용자 요청 없이 최신 버전으로 바꾸지 않는다.
- 이름·별칭은 정규화한 뒤 정확히 일치시키는 것을 우선한다. 부분 일치 후보가 여러 개라면 선택을 묻는다.
- 목록은 ID·이름·비율·상태·실제 미리보기를 보여 준다. retired 버전은 기본 선택 목록에서 제외한다.
- 동일 디자인의 여러 버전은 한 템플릿으로 표시하고 필요한 경우 버전 선택을 펼친다.

## 7. Schema 외 추가 검사

JSON Schema 검증 이후 다음을 별도로 검사한다.

1. (ID, version) 조합과 템플릿 내 layout.id는 중복되지 않는다.
2. ID 숫자의 중복 표현과 이름·별칭 충돌이 모호한 선택을 만들지 않는다.
3. 영역의 x+w와 y+h는 1 이하이며 예상치 못한 겹침이 없다.
4. 자산 경로의 ID·버전은 등록 항목과 같고, 실제 파일이 존재한다.
5. 자산의 실제 경로를 해석했을 때 스킬의 허용 자산 폴더를 벗어나지 않는다. 심볼릭 링크와 경로 우회도 검사한다.
6. PPTX·이미지의 실제 형식이 확장자 및 지원 기능과 일치한다.
7. original_template을 표시하려면 실제 PPTX 구조 재사용이 검증되어야 한다.
8. ready 표시에 대응하는 개인정보·화면·호환성 검사가 실제 수행되었는지 확인한다.

검증 실패 시 목록을 부분적으로 손상시키지 않는다. 새 항목은 별도로 검증한 뒤 목록 변경을 적용한다.

## 8. 개인 호출 이름

기본 호출 이름은 ppt-maker다. 호스트에 따라 Codex는 `$ppt-maker`, ChatGPT는 지원되는 스킬 선택 UI의 `@` 호출을 사용한다. 임의의 slash 명령을 공식 기능인 것처럼 제공하지 않는다.

사용자가 자신의 호출 이름을 요청하면:

1. 소문자 영문·숫자·하이픈으로 된 짧은 이름을 확인한다. 표시 이름은 사용자의 언어로 별도 지정할 수 있다.
2. 현재 호스트의 스킬 등록 방식과 기존 이름 충돌을 확인한다.
3. 개인 스킬 위치와 생성할 파일을 확인하고 세션의 쓰기 권한·승인 요구를 따른다.
4. 실제 호출용 얇은 스킬을 만들어 설치된 본체로 연결한다. 본체 위치는 실행 시 발견한 값 또는 개인 설정으로 연결하고 공개 패키지에 개인 절대 경로를 쓰지 않는다.
5. 호출 스킬의 description은 명시적 개인 호출 용도로 한정하고 가능하면 implicit 호출을 끈다. 본체의 자동 발동 정책은 임의로 바꾸지 않는다.
6. 무해한 입력으로 호출이 실제 작동하는지 확인한다. 불가능한 호스트에서는 지원하지 않는다고 설명한다.

개인 호출 설정은 업데이트되는 본체와 분리한다. 패키지의 `tools/create-alias.mjs`는 --name, --input(ppt-maker 등), --dest(사용자가 정한 개인 스킬 상위 폴더), --dry-run을 받는다. 먼저 dry-run으로 생성할 두 파일을 확인하고 현재 세션의 파일 승인 규칙을 따른다. 공개 소스에는 개인 별칭을 만들지 않는다. 이 도구는 로컬 호출 스킬을 작성하며 호스트의 설치·재탐색 동작이나 ChatGPT 등록을 자동화하지 않는다. 본체를 이동하면 별칭을 다시 생성한다.

## 9. 기본 생성기의 범위

제목·본문·비교·로드맵·KPI·마무리 레이아웃을 지원한다. 색·글꼴·제목/본문 크기·기본 여백과 title/subtitle/body/footer 영역을 적용한다. image/table/chart와 확장 도형 스타일·정밀 패턴은 계약에 보존할 수 있지만 기본 엔진이 모두 그리지는 않는다. 원본 구조 재사용과 자동 등록·미리보기 CLI는 포함하지 않는다. 미지원 기능을 완료로 표시하지 않는다.
