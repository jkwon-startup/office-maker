# OSMU 작업 흐름

| 단계 | 입력 | 결과 | 확인 |
| --- | --- | --- | --- |
| 질문 | 대화·첨부 자료 | brief | 부족한 정보만 질문하고 답 기다리기 |
| 정규화 | 원문·출처 | canonical content | 사실·가정·단위·출처 구분 |
| 목적별 설계 | 공통 자료·템플릿 | slides/workbook/document | 세 형식의 역할과 핵심 값 일치 |
| 환경 확인 | 런타임 | doctor | 없는 기능·라이브러리 명시 |
| 생성 | 검증된 제작안 | PPTX/XLSX/DOCX | 형식별 생성·파일 검사 |
| 검토 | 실제 파일 | 형식별 보고서 | 화면·수식·내용·앱 호환성 |
| 전달 | 성공한 파일·보고서 | 링크·실제 상태 | 부분 실패와 미실행 검사 명시 |

`output-map.json`이 형식·확장자·제작안 키·생성기 관계를 정의한다. 로컬 파이프라인은 API에 자료를 보내지 않으며 세 생성기를 호출한다. 기본 변환은 가상 예시 또는 시작안에 적합하며 강의·제안서 등은 스킬이 상세 제작안을 구성해야 한다.

`--dry-run`은 계획과 핵심 검증만 수행하고 파일을 쓰지 않는다. 실행에는 명시적 결과 폴더와 서로 다른 체크포인트 폴더가 필요하다. `checkpoint.json`은 입력·선택 형식의 해시와 형식별 결과를 기록한다. 성공 파일의 해시까지 맞아야 재개 시 건너뛴다. 입력 변경, 파일 변경 또는 기존 결과 충돌 시 새 실행 폴더를 사용하거나 사용자가 해결한다. 같은 실행을 동시에 돌리지 않는다.

최종 파일은 덮어쓰지 않는다. 체크포인트만 재개를 위해 교체한다. 실패한 형식은 재시도할 수 있으며 성공한 형식은 보존한다. 재시도 중 체크포인트에는 이번에 갱신한 결과와 아직 순서가 오지 않은 형식의 기존 결과를 함께 저장한다. 복구에 다시 실패하거나 성공 파일을 건너뛰더라도 뒤에 있는 성공 기록이 누락되지 않게 한다. 실패 상세는 현재 실행의 보고서에서 확인하고 고객 원문을 공개 로그에 남기지 않는다.

PPT의 출처 ID 존재 여부만으로 주장 근거가 증명되지는 않는다. 형식 간 의미·수치 일치는 스킬의 검토 단계에서 확인한다. Excel의 수식은 앱에서 재계산하고 DOCX/PPTX 화면은 별도 렌더링으로 확인해야 한다. COMPLETE는 파일 생성 완료이며 시각 검토 완료가 아니다.
