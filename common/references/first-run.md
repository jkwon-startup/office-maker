# 첫 실행 준비

사용자가 설치된 스킬을 선택하면 실행자가 준비를 담당한다. 캐시 경로를 찾거나 유지보수자 테스트 명령을 실행하라고 사용자에게 요구하지 않는다.

1. 로드한 SKILL.md의 실제 위치에서 두 단계 위의 패키지 루트를 찾는다. `package.json`, `plugin.json`, 공통 런타임과 형제 스킬이 있는지 확인한다. 원본 저장소의 경로를 설치된 복사본의 경로로 가정하지 않는다.
2. 필요한 입력과 저장 위치를 먼저 확인한다. 현재 호스트에 코드 실행 도구와 Node.js 20 이상이 있는지 확인한다. 호스트에서 제공하는 런타임도 사용할 수 있다. 실행 도구가 없으면 제작안을 제공하고 파일 생성은 미실행이라고 설명한다.
3. `node <실제-패키지-루트>/common/runtime/setup.mjs --check`를 실행한다. 이 명령은 읽기만 하며 READY이면 기존 런타임을 재사용한다. NEEDS_SETUP의 종료 코드 2는 준비가 필요하다는 뜻이다.
4. 의존성이 없으면 현재 세션의 설치·네트워크·파일 권한을 확인하고 `node <실제-패키지-루트>/common/runtime/setup.mjs --install`로 잠금 파일의 의존성을 준비한다. 설치 후 READY가 확인되어야 생성한다. 이미 허용한 작업은 다시 승인받지 않는다. 이 명령은 npm 설치 스크립트를 실행하지 않으며 외부 모델이나 API 계정을 요구하지 않는다.
5. 플러그인 위치가 읽기 전용이면 사용자가 선택한 작업 공간 안의 쓰기 가능한 비공개 실행 폴더를 정한다. 저장 경로를 알리고 호스트의 승인 규칙을 따른 뒤 `node <실제-패키지-루트>/common/runtime/setup.mjs --install --dest <실행-폴더의-절대-경로>`로 공개 패키지만 복사한다. 고객 파일·설정·기존 결과·개인 템플릿·Git 정보는 복사하지 않는다. 대상 폴더가 있으면 덮어쓰지 않는다. 이전에 준비한 복사본은 그 복사본의 setup.mjs로 확인해 재사용한다.
6. 출력 JSON의 `root`를 이후 모든 생성기·스키마·공개 템플릿의 기준으로 사용한다. OSMU는 한 번 준비한 같은 런타임을 세 형식에 공유한다. Node 경로에 공백이 있으면 셸 인자별로 안전하게 인용한다.

사용자 자료·제작안·결과·체크포인트·개인 라이브러리는 사용자가 지정한 비공개 위치에 둔다. 의존성이 준비되지 않거나 설치가 실패하면 원인과 가능한 조치를 설명한다. 준비 검사는 글꼴·화면·Microsoft Office 호환성 검사와 구별한다.
